## 2. 확정된 사실 (전부 실측 또는 문서 대조)

### 2-1. 토큰 폭 — `ctrl00_parser_audit.md`

```
01..DC   1바이트 글리프
DD..E0   2바이트 글리프
E1..FF   2바이트 제어코드 (명령 + 인수)
00       문자열 종료
```

**E1 이상이 전부 제어다.** v268~v285는 `E2` 와 `E3..E8` 만 제어로 보고
`E9`/`EA` 를 조회표 글리프로 취급했다. 제어를 글자로 읽으면 그 뒤가 통째로
어긋난다.

### 2-2. ASCII 범위 — `ascii_glyph_rule_repair_report.md`

```
유효   인덱스 0..25 만 ASCII (index = ASCII - 32).  0 은 공백, 1..25 는 ! ~ 9
무효   인덱스 26..94 는 ASCII 가 아니라 일본어 글리프
```

문자열을 ASCII 비율로 판정하면 안 된다. 일본어 글리프가 `/` `\` 로 보여
경로 문자열로 오인된다.

### 2-3. 안전 슬롯 — `bible_current.txt`

```
안전     1바이트 0x68..0xD0 + D4/D8/DC
금지     0x08..0x64  (메뉴·숫자·HP/MP·이름창이 공유)
금지     E0..FF
```

COMM.IMG 글리프 슬롯은 대사창·이름창·세이브창·전투 UI·기술명이 **공유**한다.
대사표만 보고 "안 쓰는 칸"이라 판단하면 UI 가 깨진다. v290 이전 판들이
캐릭터 밑·로드 화면이 깨진 원인이 이것이다.

### 2-4. 초성 벌 매핑 — 폰트에서 직접 실측

8x4x4 폰트가 표준 8벌식 표와 순서가 다르다.

```
세로 모음(ㅏㅓㅣ) 받침 없음   벌0     표준과 일치
세로 모음        받침 있음   벌4     표준과 일치
가로 모음(ㅗㅛㅡ) 받침 없음   벌1     표준과 일치
가로 모음        받침 있음   벌2     표준은 5.  ← 여기가 다르다
```

벌5는 폭 5~6px 로 세로 모음용이다. 가로 모음에 이걸 쓰면 초성이 왼쪽
구석에 박혀 `을·글·슬` 이 전부 왼쪽으로 쏠린다.

`ㅜㅠ` 와 복합 모음(ㅘㅚ)은 격자 확인에서 벌4·5·7 이 후보로 겹쳐 미확정.

### 2-5. E2 확장 — `codex_notes.txt` 2026-07-14 / 07-16

```
슬롯      0x45000 + slot*0x80,  파일당 최대 79칸  (0x45000..0x477FF 예약)
디스크ID   원본이 A9 사용 → 커스텀은 81-A8(슬롯 0-39), AA-D0(슬롯 40-78)
RAM       0x80114000 + slot*0x80     ← 뱅크 변위 0x4000 필수
슬롯 배치  슬롯 시작부터 널 종료 문자열,  byte 0x7F 에 "원래 용량 - 2"
훅        0x8016BC84 JAL → lookup handler (0x8018FCD0)
          0x8016BDC0     → completion handler (0x8018FD28)
          완료 후 0x8016BE44 로 복귀
```

**반드시 지킬 것**

- `E6 01` 은 보조 문자열 안에서 안 먹는다. 공백과 자동 줄바꿈만 쓴다.
- 본문 나머지를 `9C` 로 채우면 빈 줄·빈 대화 페이지가 생긴다.
- `E2 nn` 뒤 원본 바이트와 `00 00` 경계를 보존한다. 핸들러가 건너뛴다.
- **R3000 로드 지연**: `lw`/`lbu` 결과를 다음 명령에서 바로 쓰면 안 된다.
  v0.6~v0.10 이 이걸로 실패했고 v0.11 에서 스페이서를 넣어 통과했다.
- 파일마다 **실제로 0인 슬롯만** 쓴다. 일부 파일은 뱅크 일부를 원본이 쓴다.

핸들러 코드는 `build_story_e2_bank79_v14.py` 에서 그대로 가져왔다.
새로 작성하지 말 것.

### 2-6. 글자 폭 표

```
0x8019AA11    글자별 폭 표.  0x8016B6DC 에서 lbu 로 읽어 패킷 +0x2a 에 넣는다
0x8016B344    반각 폭 6
0x8016B160    진행 폭 (전역)
```

폭이 전역 상수가 아니라 **글자마다 표에서 온다.** 빈칸만 좁히고 한글 폭을
따로 주려면 이 표를 쓴다. 인덱싱 규칙은 아직 미확정.

## 3. 실패한 경로와 이유

### 3-1. 16px 전환 (v268~v293) — 폐기

16px 은 셀이 커져 한 줄에 21칸이 안 들어간다. U 가 1바이트라 아틀라스
폭이 255px 를 못 넘기 때문에 15열로 줄여야 하고, **그 순간 모든 글자
번호가 바뀐다.**

```
대사 번호      대사표 2,878곳은 고칠 수 있다
대사 밖 번호   UI·이름표·메뉴가 어디에 적혀 있는지 전부 알 수 없다
             → 못 찾은 참조가 옛 번호로 남아 엉뚱한 그림을 그린다
```

참조를 찾으려 두 번 시도해 둘 다 실패했다.

- v269: `0x78000..0x83000` 을 널로 끊어 훑음 → 실행 코드를 문자열로 덮어
  **부팅 불가**
- v285: 포인터 추적으로 1,736곳 → 그중 파일 경로(`\XMV\OPEN.STR;1`,
  `MAP\WORLDMAP.DAT`)가 섞여 **검은 화면**

실행 파일 안에서 글자와 코드는 자동으로 구분되지 않는다. 3중 필터
(점프 목적지 배제 / MIPS 조밀도 / 원본 글리프 해독률)로 걸러도 데이터
테이블과 경로가 남았다.

또한 16px 에서 글자 아래가 잘렸다. 상수 12를 쓰는 5곳을 전부 16으로
바꿔도 해소되지 않았고 원인 미규명이다.

**12px 은 이 문제가 원리적으로 없다.** PSX.EXE 를 안 건드리니 번호가
그대로이고, 대사표 밖 글자도 원래 자리를 읽는다.

### 3-2. v235 계보 (v250~v267) — 폐기

여러 세대 재배치가 쌓여 코드 2,634종으로 부풀었고(원본은 1,041종),
무엇이 무슨 글자인지의 기록이 남지 않았다. 해독을 네 방법으로 시도해
54~57% 에서 막혔다.

```
번역문 정렬 학습        513종
같은 그림 묶기          +80종
굴림체 대조             정확도 69% — 사용 불가
게임 글꼴 조각 역산      조각 118/360, 합성 가능 3% — 실패
```

미해독으로 보이던 코드의 상당수는 **미번역 일본어**였다. 조합할 대상이
아니라 번역할 대상이다.

### 3-3. 디스크 배치

`arc1_v104_layout.xml` 은 PSX.EXE 를 뒤(533번째)에 두고 앞에 더미
284섹터를 넣는다. 스트립/동적 캐시 시절 실행 파일을 키우며 만든 배치다.
**원본 실행 파일을 쓸 때는 `arc1_original_layout.xml`** (PSX.EXE 가
2번째)을 써야 한다. v271 이 부팅 못 한 원인.

`package_test_iso.py --layout original` 로 선택한다.
