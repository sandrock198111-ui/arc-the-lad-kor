# Codex 작업 지시서 — v108 이분 탐색 (P6 글리프 이전 실패 원인 규명)

작성: Claude (설계·검증 담당) / 수행: Codex (구현·테스트 담당)

## 배경

v103은 확장 글리프를 정상 표시했다. v106/v107은 글리프를 다른 VRAM 자리로 옮긴 뒤
확장 글자가 **빈칸**으로 나온다. v104는 디스크 배치만 바꾼 것이고 EXE는 v103과 같다.

빈칸이지 깨진 그림이 아니라는 점이 중요하다. 잘못된 픽셀을 읽는 게 아니라, 그 글자가
P6 경로를 아예 타지 못하고 있다는 뜻이다.

## 정적으로 이미 검증된 것 (다시 확인할 필요 없음)

전부 v107 빌드와 v107 상태저장(`HASH-5B42E6E2F7D4A581_3.sav`, 아이템 화면)에서 확인했다.

## 관측된 실패 증상

아이템 화면 상태저장에서:

- 글자 스프라이트 38개, **U mod 12 이 전부 0** — P6 헬퍼를 탄 것 0개
- V 값이 전부 12의 배수(기본 행) — 224도 244도 없음
- 어떤 텍스트 객체에도 V=224/244 패킷이 존재하지 않음

즉 색인은 3367로 올바르게 나오는데, 그 색인으로 만들어진 패킷이 없다.

## v103 대비 바뀐 변수 (4개)

1. **행 번호** 24 → 40, 63 (따라서 V 32 → 224, 244)
2. **텍스처 페이지** 0x1B (tx=11) → 0x1F (tx=15)
3. **U 오프셋** 40 → 4 (헬퍼 `0x801FE3E8`)
4. **분류기** 인라인 4명령 → `jal` 서브루틴

넷을 한꺼번에 바꿔서 어느 것이 원인인지 갈리지 않는다.

## 지시: 한 번에 하나씩만 바꾼 빌드 3개

**기준은 v103** (`03_output/ui_hud_e7_v103_heap_reserved_glyphs_patch_only.zip`,
sha256 `9EE40993E72962F26DAFBD61CA565D4646E247D9990B79EF5122776838584FD3`).
v105/v106/v107은 기준으로 쓰지 말 것.

각 빌드는 **파일명을 새로 만들 것.** 기존 zip을 절대 덮어쓰지 말 것.

### v108a — 행만 바꾼다

- 색인 테이블: row 24 → row 40 (열·평면 유지, 15열 그대로)
- VRAM 목적지: (714, **480**) — 페이지 11 유지, U 오프셋 40 유지
- 분류기: 인라인 유지, 비교값만 32 → **224**
- 헬퍼: `addiu a3,t0,-24` → `addiu a3,t0,-40` 한 워드만
- tpage: **0x1B 그대로**

이것이 통과하면 행 변경과 V 계산은 무죄다.

### v108b — 페이지만 바꾼다

- v103 그대로 두고 tpage `0x1B` → `0x1F`
- VRAM 목적지를 (**961**, 288)로, U 오프셋 40 → 4
- 행 24, 분류기 32 비교 그대로

이것이 통과하면 페이지·U 이동은 무죄다.

### v108c — 분류기만 바꾼다

- v103 그대로 두고 분류기만 `jal` 서브루틴으로 (비교값은 32 하나만)
- 서브루틴 위치는 v107과 동일한 방식으로 예약 RAM에 배치
- 행·페이지·U 전부 v103 그대로

이것이 통과하면 서브루틴화는 무죄다.

## 각 빌드에 반드시 넣을 빌드타임 검증

- 기준 zip의 sha256을 확인하고 다르면 중단
- 손대지 않아야 할 워드는 KEEP 목록으로 값까지 대조 (v103 빌더의 방식을 따를 것)
- 쓰기 후 반드시 되읽어 확인
- **생성한 코드가 만드는 주소를 CPU처럼 따라가며 전부 대조할 것.** v105에서
  `lui`와 부호 있는 오프셋을 짝지어 `0x801EE9D0`을 가리키는 버그가 났다
- `PSX.EXE` 크기가 변하면 보고할 것 (v104 배치에서는 허용되지만 알아야 한다)

## 테스트 절차 (각 빌드마다)

1. zip 내용을 `E:\arc\out` 에 **덮어쓰기**로 풀 것
2. `arc1_v104.xml` 로 굽고 출력 이름은 `arc1_v104.bin`

5. 그 화면에서 '잎'이 보이는지 / 빈칸인지 기록

## 검토 방식

Codex 보고는 그대로 채택하지 않는다. Claude가 다음을 직접 확인한다.

- 산출된 zip을 다시 역어셈블해 바꿨다고 한 워드가 실제로 그 값인지
- 상태저장에서 VRAM 픽셀과 실제 스프라이트의 U/V/CLUT를 직접 디코딩
- 보고된 결과와 관측이 어긋나면 수정 요청을 다시 보낸다
