# Arc the Lad 1 Pilgi 16px 통합 마스터 플랜

작성일: 2026-08-21  
상태: 분석 기준선. 아직 배포 기준이나 `bible_current.txt`를 변경하지 않는다.

## 1. 현재 판단

통합 작업을 시작할 만큼 핵심 구조는 파악됐다. 다만 “게임 전체 구조가 끝났다”는
뜻은 아니다. 현재 확정 범위는 대화 렌더러, Pilgi 16px 조각, E2 단일 슬롯,
원본 대사 경계와 주요 UI 계보까지다. 메뉴·아이템·전투·선택지는 소비 경로가
서로 달라 생산 빌드에 넣기 전에 기능별 재검증이 필요하다.

두 기준선을 동시에 보존한다.

| 기준 | 용도 | 판정 |
|---|---|---|
| v197 | 번역·UI·아이템·전투의 배포 성과 | 현행 배포 기준. 바이너리 기반으로 쓰지 않고 승인된 데이터와 수정 근거를 회수한다. |
| D941D1BE | 깨끗한 원본 기반 Pilgi 16px 대화 렌더러 | PoC 런타임 통과. 새 통합 빌더의 폰트·대화 렌더 기준이다. |

동적 캐시는 폐기한다. v211 이후의 동적 캐시 이동·복원 계보도 통합 기반으로
사용하지 않는다. v200대의 성과 중 E2, UI 주소, 선택지 기하, 아이콘·텍스처
보호 가드는 기능 단위로 회수한다.

## 2. 동결할 것과 다시 만들 것

### 그대로 동결

- 원본 `00_original/arc.zip`과 그 SHA-256.
- Pilgi 16px 렌더 프로필, 공식 벌 규칙, 조각 29종.
- 논리 코드 31개와 물리 U/V/plane 매핑.
- 대화 전용 패킷 후처리 방식: 상태 D/E는 12/12로 유지하고 커스텀 패킷만
  16x16으로 만든다.
- `01..DC`, `DD..E0`, `E1..FF`, `00` 토큰 폭과 원본 종료 경계.
- E2 단일 슬롯의 조회·완료 의미, 뱅크 A의 예약 ID A9, 원본 바이트 스킵 규칙.
- `arc1_original_layout.xml`, LBA 506/506, patch-only 멤버 검증 방식.

### 원본에서 재구축

- 16px 래퍼와 좌표표의 실행파일 배치.
- 원문 텍스트 스팬 단위 E2 컴파일러와 슬롯 할당기.
- 화자 이름·콜론·본문을 원본 줄 구조에 배치하는 정책.
- 뱅크 B와 이후 후보 뱅크의 주소 분기.
- v197의 UI·아이템·기술·전투·선택지 데이터를 각 소비자 경로에 다시 적용하는
  빌드 단계.
- v197 누적 빌더의 승인된 targeted fix를 원본/최종 바이트 가드가 있는 작은
  패치 단위로 회수하는 작업.

### 참고만 하고 계승하지 않음

- v298~v305 UI 시험 빌드: 주소 매칭과 안전 감사에는 유용하지만 전부 runtime
  pending이다.
- v119/v129의 resident strip: 실기 근거와 슬롯 보호는 유용하지만 확장 EXE와
  별도 VRAM 공급 구조를 그대로 가져오지 않는다.
- v314~v316: 스팬 배치·뱅크·화자 분석은 사용하되 12px 조합형 전체 빌드를
  통합 기반으로 삼지 않는다.

### 폐기

- 동적 캐시 전 계보.
- 한 대사를 E2 여러 슬롯으로 이어 붙이는 방식.
- 전역 15열/16px 아틀라스 재배치와 실행파일 전체 글자번호 추정 치환.
- v306처럼 v197 바이너리 위에서 글꼴만 다시 그리는 방식.
- 원본에서 0이라는 이유만으로 cave·슬롯·아틀라스 칸을 점유하는 방식.

상세 판정은
`01_work/analysis/johab16_integration/feature_reuse_matrix.csv`가 단일 목록이다.

## 3. 지금 확인된 첫 통합 충돌

독립적으로 성공하거나 유망했던 구성요소가 같은 메모리를 소유한다.

| 범위 | 현재/과거 소유자 | 충돌 |
|---|---|---|
| `0x8018FCD0..0x8018FDC5` 245B | D941 16px 래퍼 196B / E2 조회·완료 핸들러 | 동시 수용 불가 |
| `0x801A7460..0x801A7860` 1024B | D941 좌표표 62B / v0.41-v42 UI decoder·table 748~1010B | 첫 바이트부터 중복 |
| `0x80193B44..0x80193BC4` 128B | v314-v316 조합 전진 helper | 두 상태의 영 확인만으로는 수명 증명이 부족 |
| `0x801A2074..0x801A2304` 656B | 원본 zero, 과거 P6/프레임 실험 코드 | 새 래퍼+표 후보이나 전체 장면 수명 감사 필요 |

따라서 첫 코드는 대사를 더 넣는 코드가 아니라 **훅·cave 소유권 레지스트리와
재배치 검증**이다. 잠정 배치는 다음과 같다.

1. `0x8018FCD0` cave는 E2 조회·완료 전용으로 되돌린다.
2. 현재 16px 래퍼 196B와 좌표표 62B는 함께 들어갈 수 있는 별도 cave로 옮긴다.
3. 첫 후보는 `0x801A2074` 656B이지만, 가용 상태 전수와 실행파일 적재·초기화
   경계를 통과하기 전에는 쓰지 않는다.
4. `0x801A7460`은 UI 통합 전까지 예약 상태로 두며 16px 자산을 남기지 않는다.

현재 16px 래퍼가 조합 조각의 X 전진을 이미 처리하므로, E2와 결합할 때
v314의 별도 전진 helper는 원칙적으로 필요하지 않다. 이 가정은 첫 결합 PoC에서
RAM 패킷과 X 좌표로 다시 검증한다.

## 4. 생산 빌드의 단일 경로

최종 형태는 누적 ZIP 위에 다음 버전을 얹는 방식이 아니다.

```text
00_original/arc.zip
        |
        +-- 고정 원본 카탈로그/제어코드 사양
        +-- Pilgi 16px 폰트 프로필
        +-- 대사 컴파일러 + E2 할당기
        +-- UI 소비자별 패치 단계
        +-- 훅/cave/아틀라스 Expected Write 레지스트리
        |
        +-- patch-only ZIP + full test ZIP + original-layout BIN/CUE
```

각 단계는 변경하려는 멤버와 바이트 범위를 먼저 등록한다. 두 기능의 쓰기 범위가
겹치면 적용 순서로 해결하지 않고 빌드를 실패시킨다.

## 5. 단계와 통과 게이트

### 단계 A — 기준선·소유권 동결

산출물:

- 기능 재사용 행렬.
- 훅, cave, 아틀라스 plane, DAT 슬롯, 실행파일 문자열 풀의 소유권 목록.
- v197에서 회수할 데이터와 폐기할 런타임 코드를 분리한 목록.

통과 조건:

- 모든 계획 기능이 `inherit_exact`, `reconstruct_from_evidence`,
  `reference_only`, `discard` 중 하나다.
- 미분류 쓰기 범위와 중복 소유권이 0건이다.

### 단계 B — 16px + E2 단일 슬롯 결합 PoC

범위는 대화 한 장면과 뱅크 A 하나뿐이다. UI와 대량 번역은 넣지 않는다.

구현 원칙:

- D941 래퍼의 동작과 31개 좌표 엔트리는 바이트 수준으로 보존하되 새 cave로
  재배치한다.
- v0.11/v297의 E2 lookup/completion을 `0x8018FCD0`에 둔다.
- 한 원문 스팬은 인라인 또는 E2 하나만 사용한다. 126바이트를 넘으면 빌드 실패다.
- E6 등 제어 토큰은 원래 DAT 위치에 남긴다.
- E2 뒤 원본 바이트와 원래 종료 위치를 보존한다.

실기 게이트:

- 콜드부팅 후 긴 E2 문장이 끝까지 나온다.
- 조합 조각은 같은 X에 겹치고 한 음절이 14px만 전진한다.
- E2 종료 후 다음 본문으로 자연 진행한다.
- 같은 장면의 후속 일본어가 12x12로 직접 관찰된다.
- 훅·래퍼·핸들러가 디스크와 RAM에서 일치한다.

### 단계 C — 대사 컴파일러와 저장 용량

컴파일러는 CSV 문장을 바로 바이트로 덮지 않는다. 다음 순서로 처리한다.

1. 원본 raw를 공통 제어코드 사양으로 토큰화한다.
2. 원본 텍스트 스팬과 제어 토큰 위치를 분리한다.
3. 번역문을 화자/본문으로 구조화한다.
4. 14px 전진 기준의 실제 픽셀 폭과 64패킷 한도를 계산한다.
5. 각 원문 스팬을 인라인 또는 E2 한 슬롯으로 배치한다.
6. 원래 제어 토큰·종료자·뒤 트레일러를 재결합한다.
7. 원본 raw와 새 raw의 Expected Write를 출력한 뒤 적용한다.

필수 보고 수치는 다음과 같다.

- 전체/번역/제외/미분류 행.
- 인라인 스팬, 뱅크별 E2 스팬, 126바이트 초과, 슬롯 소진, 2바이트 미만 스팬.
- 행별 픽셀 폭, 패킷 수, 화자 정책, 제어 토큰 왕복 결과.
- 파일별 뱅크 점유와 원본 사용 슬롯 배제 수.

뱅크 B는 별도 runtime PoC를 통과한 뒤 활성화한다. C/D는 0블록이라는 사실만으로
활성화하지 않는다.

### 단계 D — 화자 형식과 줄 pitch 확정

두 항목은 대량 삽입 전에 사용자 화면 판정이 필요하다.

- 화자 정책 후보: `화자 :`를 독립 첫 줄에 두기, 또는 `화자 : 대화`를 같은 줄에
  두고 남는 본문을 다음 줄로 보내기.
- 세로 정책 후보: 현재 14px pitch/2px 겹침 수용, 상태 누수 없는 조건부 16px
  pitch, 또는 글꼴 하단을 보존한 별도 15px 표현.

두 정책을 같은 진단 장면에서 비교하고, 글자 수·슬롯 수·패킷 수의 전체 코퍼스
영향도 함께 제시한다. 화면만 보고 고른 뒤 저장 용량이 무너지는 선택을 하지 않는다.

### 단계 E — 대사 대량 삽입

대상은 확정된 2,878 원본 행과 2,679 번역 행이다. `dialogue_sites_full.csv`는
v104+ 위치 목록이므로 원본 대사 추출 기준으로 사용하지 않는다.

통과 조건:

- 2,878행 raw join 100%.
- 제어 토큰과 종료 경계 100% 왕복.
- E2 다중 연결 0건.
- 슬롯/바이트/패킷 초과를 자동 절단하지 않고 모두 명시적 실패 목록으로 출력.
- 선택지 357개는 일반 대사와 분리해 E5/E6 기하 검사를 통과.

### 단계 F — UI·아이템·전투·선택지

UI는 한 덩어리로 넣지 않고 소비자별로 진행한다.

1. 실행파일 포인터 테이블 기반 장비·아이템·기술명.
2. 대화 DAT 안의 선택지와 전투 선택문.
3. 전투 HUD와 레벨업 문구.
4. 화자명·이름창·세이브/로드 화면.
5. 원형/사각형/십자/START 아이콘과 기술 범위 텍스처.

각 소비자는 원본 위치, 포인터 모집단, 글리프 공급 방식, 최대 폭, 테스트 장면을
따로 가진다. v197 바이너리를 덮어씌우지 않고 v197에서 승인된 문구·주소·canary를
원본 기반 단계로 옮긴다.

UI decoder를 가져오기 전에 `0x801A7460` cave 전체 배치를 확정한다. v0.42의
공유 문자열 풀 포인터 누락을 반복하지 않도록 포인터 카탈로그의 resolved,
excluded, unknown 합이 전체 모집단과 같아야 한다.

### 단계 G — 단일 통합 빌드와 회귀

정적 게이트:

- 입력 해시와 모든 원본 expected bytes.
- 멤버 크기·LBA·COMM 307/667/891.
- 훅 target, delay slot, RA, 즉시 load-use, 모든 return path.
- 아틀라스 plane과 게임 아트 canary.
- 포인터 범위, E2 owner, 고아 참조, 패킷 64.
- 동일 환경 2회 이상의 재현 빌드 해시.

실기 게이트:

- 콜드부팅과 자연 진행.
- 일반 대화, 화자 대화, 선택지, 아이템명, 기술명, 전투 HUD, 레벨업,
  세계지도, 저장/불러오기.
- 16px 하단 행, 줄 겹침, 창 경계, 다음 일본어 12px 복귀.
- v197에서 사용자 확인한 아이콘·아이템·전투·기술 범위·선택문 항목의 회귀 0건.

## 6. 바로 다음 구현 목표

다음 산출물은 대량 번역 빌드가 아니라 `J16-E2-A` 최소 결합 PoC다.

2026-08-21 정적 진행 상태: 아래 1~4는 `J16E2A`로 구현·검증했고 5의 실기
게이트를 기다린다. 시험 문자열은 새 조각을 추가하지 않도록 기존 D941 조각만
사용한 `가 나 고 구 과 워`이며, S1011 첫 7바이트 스팬을 bank A slot 0으로
확장한다.

1. 가용 세이브 상태와 원본 EXE를 이용해 `0x801A2074` 후보 cave의 생존·쓰기
   여부를 전수 감사한다.
2. 16px 래퍼와 좌표표를 그 후보에 재배치한 뒤 D941 진단문을 재현한다.
3. `0x8018FCD0`에 E2 bank-A lookup/completion을 넣는다.
4. S1011의 이미 실패 원인이 알려진 긴 대사 하나를 원문 스팬 단위 E2로 넣는다.
5. 자연 진행, 후속 일본어 12px, RAM 훅·패킷·파서 포인터를 함께 확인한다.

이 게이트가 통과하기 전에는 bank B/C/D, 전체 2,679행, UI를 한 빌드에 섞지 않는다.
