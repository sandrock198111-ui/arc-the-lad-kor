Core Technical Lessons
- Japanese original uses 12x12-ish CJK output. Korean output through the Japanese rendering path is possible.
- COMM.IMG contains shared font/UI graphics. Changing shared slots can corrupt names, menus, battle UI, numbers, and other Japanese text.
- Safe current text style is constrained to existing block lengths.
- Remaining space should not be filled with 0x00, because that can act as terminator/control and break script flow.
- Existing successful approach uses safe filler/blank display slot behavior, with high-slot glyphs that were verified.
- E0-FF must not be used as general Hangul single-byte codes. Earlier tests caused missing glyphs/progression problems.
- Low slots 0x08-0x64 caused mixed Japanese/Hangul glyph leakage in later screens. Treat this as failed unless a new controlled proof is made.
- UI/menu/battle text cannot be solved by just changing COMM.IMG; UI text source bytes need separate identification.
