# P6 독립 렌더러 연구 방향

작성일: 2026-07-28

## 결론

웹 작업에서 제안된 P6 전용 글리프 페이지와 전용 렌더러 방식은 계속 시험할 가치가 있다.

이 방식은 기존 패치를 조금 수정하는 방식이 아니라, 글리프 코드 영역과 VRAM 저장소 및
렌더링 경로를 기존 경로에서 분리하려는 연구 방향이다. 성공하면 기존 글리프를 돌려 쓰면서
발생했던 아이콘, 캐릭터, 아이템명 충돌과 과도한 명칭 축약을 줄일 수 있다.

단, 현재 P6 방식은 연구 후보이지 승인된 게임플레이 기준본이 아니다. 기존 성공본을
대체하거나 기존 E2/E9/EA 구조를 폐기해서는 안 된다.

## 기존 방식과의 차이

- 스토리 E2 확장: 기존 스토리 렌더러와 글리프 구조를 확장한다.
- UI E9/EA 확장: `COMM.IMG`에서 런타임 검증된 희소 물리 공간을 재사용하고 조회표로
  연결한다.
- P6 연구안: 별도 마커, 별도 VRAM 페이지, 별도 렌더링 경로를 사용해 기존 페이지와
  물리적으로 분리하는 것을 목표로 한다.

따라서 P6는 기존 E2/E9/EA의 단순 재시도가 아니라, 저장 공간 충돌 문제를 직접 겨냥한
독립 연구 분기다.

## 보존해야 하는 기준점

- 스토리 E2 확장은 폐기하지 않는다.
- 런타임에서 성공한 UI E9/EA 구조를 폐기하지 않는다.
- `v0.41` UI 글리프 저장소 성공 기준과 기존 동결 백업을 보존한다.
- `v0.39` 비상 롤백 기준을 보존한다.
- `v0.71`은 고페이지 렌더러 실험 이전의 즉시 롤백 기준으로 보존한다.
- `v0.74`의 RA 보존 트램펄린 분석 결과를 유지한다.
- P6 시험은 위 기준본의 이름이나 백업을 덮어쓰지 않는 별도 실험으로 수행한다.

## v81 실패에서 확인된 문제

v81은 이름과 달리 단일 변수를 시험하는 최소 패치가 아니었다.

v80과 비교하면 다음 변경이 동시에 들어갔다.

- `PSX.EXE`: 416개 바이트 변경
- `COMM.IMG`: 10,080개 바이트 변경
- `31/S3032.DAT`: 291개 바이트 변경
- `S3032.DAT`의 12개 대사 레코드가 함께 변경됨

따라서 v81의 정지만으로 아래 원인 중 하나를 선택할 수 없다.

- P6 렌더러 또는 복귀 경로 문제
- P6 전용 VRAM 페이지나 GPU 패킷 문제
- `S3032.DAT` 문자열 또는 제어 코드 문제
- 번역 뒤 실행되는 후속 이벤트 명령 문제

v81 실패는 P6 설계의 실패를 증명하지 않는다. 동시에 v81을 성공에 가까운 증거로도
사용할 수 없다.

## v82 최소 격리 시험 조건

다음 조건을 모두 만족해야 최소 시험으로 인정한다.

1. 원본 일본판 `31/S3032.DAT`에서 시작한다.
2. 시험 대상 대사 한 곳만 변경한다.
3. 시험 문구는 P6 전용 네 글자 `분리성공`만 사용한다.
4. 대사 레코드의 종료 코드, 제어 코드, 후속 이벤트 명령과 분기 구조를 보존한다.
5. 기존 텍스처 페이지의 빈칸을 안전 공간으로 추정해 사용하지 않는다.
6. P6 전용 페이지와 전용 렌더러에 필요한 변경만 적용한다.
7. 이전 실험의 광범위한 `S3032.DAT` 변경을 가져오지 않는다.
8. 실제 ZIP을 만들기 전에 기준본과 파일별/바이트별 diff를 검증한다.
9. 깨끗한 이미지에 패치하고 완전 콜드부팅한다.
10. 실험판 실행 코드를 포함한 에뮬레이터 상태저장을 불러오지 않는다.
11. 같은 메모리카드 저장 또는 직접 진행으로 시험 장면에 진입한다.

## 런타임 판정 기준

### 성공

다음을 모두 만족해야 한다.

- 장면 전환이 정상 종료된다.
- 시험 위치에 `분리성공` 네 글자가 정확히 출력된다.
- 입력 후 다음 이벤트로 진행된다.
- 기존 한글 대사, UI, 아이콘, 캐릭터 및 전투 그래픽에 새 회귀가 없다.

한 장면 성공은 P6 경로의 개념 증명이다. 게임 전체 안정성을 증명하지는 않는다.

### 실패 시 필수 증거

정지 상태를 입력 대기라고 추측하지 않는다. 정지 즉시 아래 값을 확보한다.

- PC
- RA
- SP
- 현재 이벤트/스크립트 포인터
- 현재 문자열 포인터
- 렌더러 진입 전후 레지스터
- 해당 주소 주변 명령과 RAM

이 값으로 먼저 다음 두 부류를 구분한다.

1. P6 렌더러, GPU 패킷 생성 또는 복귀 경로 안에서 정지
2. 이벤트 인터프리터, 문자열 종료 또는 후속 이벤트 명령에서 정지

이 분류 없이 새 패치를 연속으로 만들지 않는다.

## 중단 및 롤백 기준

- 기존 성공 화면이나 진행성이 한 곳이라도 후퇴하면 실험판을 기준본으로 승격하지 않는다.
- 원인 미분류 상태에서 세 번째 변형 패치를 만들지 않는다.
- 전용 페이지가 캐릭터, 아이콘, 커서 또는 전투 텍스처와 충돌하면 즉시 롤백한다.
- 상태저장에 포함된 구버전 실행 코드와 새 디스크 패치를 혼합해 판정하지 않는다.
- 실패 실험의 ZIP 이름을 재사용하거나 성공 기준 백업을 덮어쓰지 않는다.

## 성공 가능성 평가

현재 증거에 근거한 연구 판단이며 보장 수치가 아니다.

- 최소 시험으로 P6 경로의 가능 여부를 판별할 가능성: 80~90%
- P6를 게임 전체에 안정적으로 적용할 가능성: 60~75%
- 연구 가치: 높음

P6 연구는 계속할 가치가 있지만, 먼저 최소 A/B 시험으로 실행 경로를 증명해야 한다.
실제 v82 ZIP이 확보되거나 재현된 뒤 정적 diff 검증을 통과해야 런타임 시험으로 넘어간다.
