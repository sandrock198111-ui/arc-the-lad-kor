아크더래드1 PS1 일본판 한글화 바이블 추가 기록 - v127
작성일: 2026-08-04

============================================================
1. v127의 작업 범위
============================================================

사용자 제공 세이브 슬롯 1~7을 실제 PS1 RAM과 파일에 매칭했다.
- 슬롯 1~3: 32/S3051.DAT
- 슬롯 4~5: 32/S3062.DAT
- 슬롯 6: 31/S3024.DAT
- 슬롯 7: C1/SC051.DAT

수정 결과:
1) 미번역 병사 대사 번역
2) 다른 폰트로 보이던 큐 수정
3) 스킬 범위 십자 그래픽 복원
4) 은혜의 정령 존댓말 통일
5) 아이템 획득문은 기존 시스템 문체 유지
6) 화자: 대화 규칙 복원
7) 전투 진입 선택지 문구 및 E5/E6 커서 구조 복원

============================================================
2. 가장 중요한 새 구조 결론: v109를 그대로 합치면 안 된다
============================================================

v109 당시에는 스킬 범위 그래픽이 있던 COMM.IMG의 16셀에서
룩업 테이블이 참조한 글리프가 달/늘 두 개뿐이라고 판단해 두 글자만
옮기고 원본 그래픽을 복원했다.

그러나 v126에서는 그 16셀의 46개 plane이 실제 한국어 직접 코드로 사용된다.
예: 구/국/궤/그/긴/께/남/냐/되/케/켜/쿠/곳/키/타/토/고/활/같/트/폐/
문/머/뀌/금/규/:/혼/피/촌/잇/때/결/먹/립/론/레/또/든/더/달/늘/년/네/꾸.

따라서 v109의 2글자 이동만 현재 계보에 적용하면, 범위 그래픽은 돌아와도
위 글자 수십 개가 사라진다. '과거 해결법이 존재한다'와 '현재 계보에 그대로
합칠 수 있다'는 서로 다른 명제다.

============================================================
3. v127의 해결법: 네 번째 상주 글리프 스트립
============================================================

- COMM.IMG 범위 그래픽 16셀을 원본 arc.zip과 바이트 단위로 동일하게 복원.
- 그곳에 있던 실제 사용 글리프 46개를 새 strip D로 그대로 이전.
- strip D 위치:
  VRAM page 15,1
  x=961, y=368, width=39 halfwords, height=12
  physical row 52, V=112
  52칸 중 47칸 사용(이전 글리프 46 + 큐 1)
- 기존 A/B/C 스트립은 바이트 단위로 그대로 유지.

직접 코드 DD~E0는 기존 산술 계산 후 physical index를 얻는다.
v127은 반환 직전에 remap helper를 거쳐, 범위 그래픽과 충돌한 46개 index만
strip D의 대응 index로 바꾼다. 문자열 자체 수천 곳을 다시 쓰지 않는다.

remap table:
- RAM 0x801FF7F4..0x801FF833
- 범위 행 10~13, 열 2~5의 64 plane을 1바이트 표로 표현
- 실제 글리프 46개만 strip D slot 번호를 가지며 나머지는 FF

renderer 변경:
- helper가 row 40/63/53 외에 row 52도 U+4 처리
- classifier가 V 224/244/124 외에 V 112도 high page로 분류
- frame routine이 매 프레임 strip D를 네 번째 LoadImage로 업로드

메모리:
- strip D 0x801FF44C..0x801FF7F3
- 새 frame routine 0x801FF83C..0x801FF8A3
- heap base 0x801FF44C -> 0x801FF8B0
- 보수적 경계 0x801FFA60까지 432바이트 남음

디스크:
- PSX.EXE 585728 -> 587776바이트, 정확히 1섹터 증가
- t_size 0x8E800 -> 0x8F000
- 반드시 arc1_v104.xml 계열 배치를 사용한다.

============================================================
4. 큐 폰트 문제
============================================================

EA 7A의 큐는 physical index 1338을 가리켰고, 같은 index를 기존 못도 공유했다.
따라서 index 1338을 직접 다시 그리면 못이 깨진다.

v127은 큐만 strip D slot 46 / physical 4414로 분리했다.
새 큐는 현재 빌드의 정상 쿠에서 ㅋ 부분, 유에서 ㅠ 부분을 조합했다.
못의 physical 1338은 변경하지 않았다.

============================================================
5. 대사 및 선택지 규칙
============================================================

- 슬롯 1: 32/S3051.DAT 0x48D62를 E2 slot 1로 이전.
- 슬롯 4: 32/S3062.DAT E2 slot 3의 문장만 존댓말로 수정.
- 슬롯 5: '만능약을 손에 넣었다.' 유지. 번역 CSV에서 같은
  '...을/를 손에 넣었다.' 계열이 70행 확인되어 시스템 문체와 일치.
- 슬롯 6: 31/S3024.DAT 0x46262를 E2 slot 0으로 이전하고
  '노인: 대화' 형식으로 통일. E2 안에 E6 01을 넣지 않는다.

슬롯 7 선택지:
- C1/SC051.DAT의 7개 전투 진입 본문을 원본에서 다시 가져온다.
- E5 두 곳과 E6 두 곳의 위치를 원본과 완전히 동일하게 보존한다.
- prompt와 두 선택지만 E2로 바꾼다.
- 문구: '전투를 시작하시겠습니까?' / '시작한다' / '돌아간다'
- 선택지 본문 전체를 capacity-2로 건너뛰면 커서 행이 어긋난다.

6. 검증 경계
============================================================

정적 검증 완료:
- 변경 파일 6개만 존재
- COMM.IMG 범위 16셀 원본과 완전 동일
- 이전 46글리프와 큐 strip D readback 일치
- 기존 A/B/C 스트립 무변경
- 룩업 테이블은 큐 항목 하나만 변경
- E5/E6 위치 원본과 완전 동일
- 슬롯 5 무변경
- 선언하지 않은 변경 바이트 0
- ZIP 재읽기와 SHA-256 재현 성공

런타임 검증은 별도다.
- arc1_v104.xml로 이미지 생성
- 콜드 부팅
- 제공된 슬롯 1~7 확인
- 특히 슬롯 3 범위 십자와 일반 대사 글자 회귀를 함께 확인
- 슬롯 2 큐와 못이 각각 정상인지 확인
