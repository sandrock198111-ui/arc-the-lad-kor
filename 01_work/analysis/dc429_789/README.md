# V363 커서/화자 개행 후속 조사

2026-09-06 사용자: V363 대사는 잘 나오며 선택 커서 위치·이동거리와 화자 뒤 개행은 추가 수정 필요.

## 실측과 원인

- 상태7 SHA256 `6bce138c3f3ae174d123e3cdfa681e961b21258f8871c94527345cab94476825`, 상태8 `4e5ae9743abb32b10046d44c12669b7d5cb5bf2cd04de28da00b0544265d7493`. 둘 다 내부 V363_DIALOGUE_TRIAL_TEST다.
- 선택 글자 첫/둘째 행의 sprite Y=64/80, 높이16. 커서 첫 꼭짓점은 (46,59)/(46,73), 중앙 꼭짓점은 (53,65)/(53,79). 커서 이동14px vs 글자 행 간격16px다. 선택행을 내려갈수록2px씩 정렬 오차가 증가한다.
- 실제 삼각형 패킷은 활성OT의 0x801F2FD4/0x801F2FE8(양쪽 버퍼), command0x21이다. 상태9에서 같은 primitive가 진행 안내 모양으로 쓰이므로 이 공통 primitive 자체를 전역 이동시키면 안 된다.
- 좌표 생산자는 선택 갱신 함수0x8015A640의0x8015A6E0..0x8015A72C다. 선택번호와 기준행을 각각 `((n<<3)-n)<<1` 즉14배한다. X의 별도 열 계산은12배다. wrapper0x8015A750→setter0x8016D278→0x801F2FC4/6→draw0x8016D2B8 순서다.
- 캡처 RAM의 해당 code와 현재 EXE가 byte exact임을 검사하고, RAM-copy Unicorn에서0x8015A6E0..0x8015A728 계산을 실행했다. 선택0/1 및 마지막delay-slot의-1 적용 결과가 캡처 좌표(46,59)/(46,73)와 각각 일치한다. 입력 반복/취소/확정 이동범위를 새로 실행한 검사는 아니다.
- 과거 V347 기록의 “현행 선택 커서 행 간격16px”는 이번 실제 소비 경로에서는 틀렸다. 다른 UI나 텍스트 line pitch를 선택 커서 이동 검증으로 확대하지 않는다.

## 화자 개행 모집단

상태9 SHA256 `9f35b6dc61cda3376b6f8df90dc65e949340ec4c67921c7211ca198203f5e8a5`. #1749, 6/S6054.DAT:0x45FDC:

`라마다 승려:\n이거 이거. \n그린 슬라임 버스터 여러분.`

CSV 표시문구가 아니라 최신 DAT의 E2 payload/skip를 따라 출력 스트림을 조사했다. 기존 원문표2,878행 중 첫 강제개행 앞이 콜론으로 끝나는 짧은 화자인 후보147건/42파일. 6/S6054.DAT에44건. 원문표 밖에 있는0x4395A의 `승려:\n수행하러 오셨습니까?`도 별도 추가 대상이다. 후보147은 의미 확정/레이아웃 전수 통과/게임 전체 누락0의 의미가 아니다.

처음~11번째 도전 안내11건 중10건에 화자 뒤 E6가 남았다. 9번째(#1776)만 한 줄로 이어진다. 대상은 #1760/1762/1764/1766/1768/1770/1772/1774/1778/1780. 실패 후 재도전 안내#1746도 개행 후보에 포함된다.

## 수정 계획과 위험 (아직 게임 변경 없음)

1. 선택 전용 좌표 생산자의 행 계산14→현행 글자 행 간격16 및 기준 위치를 검산한다. 공유 triangle setter/draw와 기존 전투 범위 커서는 보존한다. 열 간격12는 가로 다중 선택의 별도 검증 없이 변경하지 않는다.
2. 화자 뒤 첫 E6를 단순 전역삭제하지 않는다. 대상별로 `화자: 본문`을 같은 줄로 만들고 자동wrap/64출력 제한/후속 E5행/기준행을 함께 검증한다. E2 metadata, 이벤트/변수/대기 제어는 별개 보호한다.
3. 이전 V191에서 텍스트만 올라가고 커서가 남았던 실패를 회귀 조건으로 삼는다. 세로2항목 외 기존 가로/복수행 선택, 상단/하단 대화창 및 끝에서의 이동을 확인해야 한다.
4. 새 DAT/EXE 수정과 빌드는 이 조사에 포함되지 않는다. V363 사용자 확인된 문장/타이틀/글꼴/성공 UI는 기준으로 보존한다.
