## 경계와 수정 근거

- #2148 화자 E601만 A1 A1로 교체한다.
- #2151 E283, #2152 E286은 해당 DAT 전체 바이트 검색에서 각각 호출 1개이며 실제 본문 토큰/캡처로 확인됐다. 기존 completion 7→5로 각각 건너뛰는 패딩 2바이트를 회수하여 어절 경계 개행에 사용한다. 신규 슬롯/메모리 예약은 없다.
- #1742 E2DE도 호출 1개다. 앞부분 ‘항상 목적을’은 기존 Bank-B13에, `E601 + 가지고 행동하십시오.`는 기존 본문 범위에 둔다. completion17→3으로 반환 위치를 명시적으로 조정한다. E6를 확장 슬롯 안에 넣지 않았다.
- 네 본문 최종 NUL과 다음 이벤트 위치는 원래 위치 그대로다. Expected Write 전체를 불변 입력에 대조한 뒤 복사본에만 적용한다.

## 검증

1. 원본에서 재현하는 기존 `previous.prepare()` 체인이 고정 V370 ZIP과 동일한지 확인하고, V371 재실행 ZIP byte-exact를 확인했다.
2. 실제 제출 상태 네 개에서 본문/사용 Bank 구간을 정확히 찾아 RAM 복사본에 교체했다. 원래 상태 파일에는 쓰지 않았다.
3. 실제 MIPS 루틴 8016B880/8016B8C8, 창 (46,32,228,208), 주 객체 801F9D44로 렌더링했다. 개입은 창 초기화와 본문 호출이며 정상 플레이 전체를 재현한 것은 아니다.
4. 수정 전 패킷 수와 모든 문자 XY가 제출 캡처와 일치한다. 수정 후 행별 문자열 exact, 연속 행 Y32/48/64/80, 64패킷 이하, 원래 최종 source pointer 복귀를 확인했다.
5. 추출 CSV 2878행을 기준으로 현재 ZIP의 확장 토큰을 전후 대조한 결과 변경된 행은 정확히 #1742/#2148/#2151/#2152뿐이다. 이 모집단 밖의 텍스트에 대한 전수 의미 검증 주장이 아니다.
6. 새 원본 트리에서 만든 최종 디스크: 506 데이터 파일 LBA, 164 패치 멤버 readback PASS. 이전 디스크와 507 extent/크기 동일. 변경 31섹터의 양쪽 EDC/ECC 62검사 PASS, 허용 변경·생성 시각 외 payload 차이 0.

초기 국소 후보에서 확인해 폐기한 문제: 화자 개행만 연결하면 #2152의 ‘는’이 고립됨. #1742의 첫 행이 자동 개행 경계에 정확히 차는 상태에서 E6를 추가하면 빈 둘째 행이 생김. 최종본은 행별 exact 검사를 넣어 이 두 경우를 방지한다. 초기 검증의 미사용 Bank-B 전부0 검색은 중복되어 실패했으므로 실제 호출하는 Bank 범위만 식별하도록 수정했다.

## 남은 확인

- 실제 GPU 표시, 연출 재생 시간/진행 입력 및 콜드부팅 후 해당 장면 재진입은 사용자 확인 전이다. CPU 패킷 확인을 전체 실기 통과로 표현하지 않는다.
- 이전 화자 개행 보류 29건 중 이번 3건을 해결했으며 나머지 26건, 콜론 없는 후보 65건, 전 게임 말투 검토는 별도 남아 있다. 전체 전수 수정 완료나 배포판이 아니다.
- 확인 방법: 새 CUE로 콜드부팅 → 메모리카드 진행 데이터에서 해당 로크톨 연설/라마다 승려 대사를 다시 실행한다. 구 상태저장은 구 RAM 본문을 복원할 수 있어 새 패치 반영 확인 근거로 쓰지 않는다.
- bible_current는 사용자 확인된 성공 기준을 유지한다. 실제 적용은 changelog, 테스트/실패는 test_log, 확인한 경계는 codex_notes에 기록했다.
