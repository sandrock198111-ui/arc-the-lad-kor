# 커서/슬라임 충돌 해결안 검토 — 구현 승인/완료 아님

전제: 새 빈 VRAM은 가정하지 않는다. 현재 게임/CSV/세이브/빌드는 변경하지 않는다.

## 우선 후보의 근거와 미확정 조건

- 실제 전용 draw 0x8011ED24와 helper0x8011EFEC를 읽었다. 각 기존 FT4 공간 stride는0x28(40B); 9개 UV 유형으로 중앙/바깥 형태·회전을 분기한다. 범위>=2의 바깥 표시에는 기존 시간 판정이 있다. 이를 일반 사각형9개로 무조건 바꾸면 범위 의미가 달라질 수 있다.
- 단색 닫힌5꼭짓점 polyline은 command1+vertex5+terminator1+DMA tag1=32B여서 형식상 기존40B 안에 든다. 이것은 단색/1px 윤곽의 예산 검사일 뿐 원본 그라데이션/굵기/점멸을 완벽히 재현한다는 뜻이 아니다.
- GPU 명령 근거: https://psx-spx.consoledev.net/graphicsprocessingunitgpu/#gpu-render-line-commands (2026-09-06 열람). polyline 종료토큰, 하단/우측 끝 포함 규칙과 FT4의 끝 제외 규칙 차이를 다뤄야 한다.
- 위험: 9개 유형의 형태/방향 누락, 좌표변환 뒤 1px 어긋남, 화면 경계 clipping, 반투명/dither/색, 기존FT4가 갱신하던 tpage와 다음 소비자의 상태, DMA word count/연결, 이중버퍼, 함수 복귀/지연슬롯.
- 기존 커서 uploader/RLE 전용 코드를 대체 가능한지 크기/호출범위를 별도 검사한다. 코드 저장 공간이나 packet 버퍼 추가 여유도 추정하지 않는다. 업로드를 멈춰도 이미 저장된 오염 VRAM이 자동 복원되는 것은 아니므로 변경판 검증은 콜드부팅부터 한다.

## 판정/중단 기준

다음 작업을 승인받으면 먼저 별도 실험에서 커서의 선택/범위 계산을 건드리지 않고 출력만 바꿀 수 있는지 검증한다. 사용자 외형 비교 전에 실사용 빌더에 넣지 않는다. 최대범위9유형, 이동/취소/확정/아이템/스킬, 슬라임 모든 관측 프레임, 장비↔전투 재진입, PSP는 별도 확인 대상이다.

신규 VRAM을 요구하거나, 전체 폰트 이동/다른 몬스터 렌더 변경/검증되지 않은 RAM 확보가 필요해지면 국소안으로 취급하지 말고 재검토한다. 원본 외형 동일성이 필수라면 이 단색 선 방식은 승인 가능한 최종안이 아니며 원본 테두리 재현 비용부터 따로 산정한다.

현재 결론: 비텍스처 커서가 충돌 자체를 없앨 구조적으로 유리한 후보지만 아직 안전성/외형/실기 성공 미검증. 성공 확률을 수치로 보증할 근거 없음. 수정이나 빌드 없음.
