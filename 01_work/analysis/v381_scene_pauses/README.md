## 대기 누락의 범위와 수정

이전 검사는 완성된 글자 출력과 종료 주소 중심이라, 대사 사이 연출이 사라진 문제를 검출하지 못했다. 이번에는 완성 출력 함수와 별도로 실제 점진 출력 함수 8016BB10을 반복 실행했다.

- S205C의 원장 전체를 비교했다. #631/632/633/634/636/638/639/642/643/644/648/649/650의 13행에서 E4 총43개가 누락되어 있었다.
- 처음 제보와 연결된 #644/648/649의 15개를 V380에서 복원했다. 나머지 10행의 28개를 V381에서 복원했다.
- 정상인 #640까지 포함한 이 장면의 E4 보유 **14행 모두** 원문의 E4 순서·매개변수와 일치한다. 다른 모든 장면의 대기까지 전수 복원했다는 뜻은 아니다.
- 한국어 어순에 맞춰 평문 구간을 E2 슬롯에 넣고, E4는 본문에 둔다. E4 순서와 대기값, 본문 길이·종료·뒤 이벤트를 유지한다. 글자 배치가 달라져 E4 물리 위치는 일부 이동한다.
- 남는 바이트는 마지막 평문 E2 completion으로 건너뛴다. 마지막 대기 뒤에 불필요한 공백 출력 시간이 붙거나 빈 줄이 늘어나는 것을 방지한다.
- 10개 추가 행은 한국어 의미와 문장을 바꾸지 않았다. 원장 한국어는 #635/644/2323의 3셀만 백업 후 갱신했다.

## 실행 증거

새 상태는 v380_followup/states.json의 전체 경로 및 SHA256으로 구별한다. 같은 이름의 이전 업로드를 사용하지 않는다. 업로드 상태를 변경하지 않았고, EXE 앵커와 대상 범위가 호환되는지 확인했다. 이름의 해시만으로 전체 디스크 버전을 단정하지 않는다.

- 제보 6개: 기존 글리프 패킷 위치/UV/CLUT 및 종료 주소를 캡처와 일치시킨 뒤 수정 결과 확인. L/R 안내도 실제 도움말 함수8016C794를 실행했다.
- #644/648/649: 원본 본문 / 수정 전 / 수정 후의 실제 점진 출력 비교. 수정 전 E4 실행0회, 수정 후 원문과 동일한 대기 횟수·카운트. 모든 변형의 최종 소스 주소 동일.
- 나머지 10행: 같은 캡처의 정상 글자 출력 환경에 각 원본/기존/수정 본문과 해당 뱅크를 격리 적재한 합성 검사. 원본/수정 후 E4 매개변수와 실제 감소 횟수 일치, 기존은0회. 이는 해당 이벤트를 처음부터 플레이한 검증과 구별한다.
- 네이티브 E4 진입은8016BBE4, 카운터 감소는8016BDE0에서 관찰한다. 매개변수에서1을 뺀 횟수만큼 감소한다. 단순히 문자열 안에 E4 바이트가 있다는 것으로 대기를 판정하지 않는다.
- 최종 빌드에서 V376~V379 및 V380 회귀 검사 모두 실행했다. 물의 신전/UI/배우/카드/선택 커서 및 기존 제보 출력 검사를 포함한다.
