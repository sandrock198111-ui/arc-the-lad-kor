# csv:4 3줄 시험 — 출력 전 차단

2026-09-09 사용자는 V371의 csv:4 / 1/S1011.DAT 한 건의 어절 조판 테스트를 요청했다. 기존 V371을 보존하고 해당 본문/슬롯만 수정하는 초안을 메모리에서 생성했다. 새 ZIP/BIN/CUE는 생성하지 않았다.

## 확인한 범위

- 본문4799E..479C7, 종료NUL479C8. E28A 단독 호출, Bank-A9 슬롯45480..454FF. 기존 completion40.
- 초안은 기존 글자코드(이의DD01 alias 포함)를 보존해 첫 줄만 슬롯에 두고 나머지 두 줄은 inline으로 배치한다. completion3, 원래 본문42B 및 종료 위치 동일. E6는 확장 슬롯 안에 넣지 않는다.
- 기존2878 CSV 행의 확장 해독 전후 차이는4번만, 다른DAT/EXE/COMM 불변인 복사본 초안이다.
- V371 상태의 확인된 Bank-A 주소114000에 해당 슬롯만 교체한 격리 RAM에서 실제 E2 처리/복귀를 실행했다. 본문은 분석용70000에 놓았으며 실제 S1011 장면 진입이나 창 폭을 관측한 것은 아니다.
- 180px CPU 출력은 첫 줄/둘째 줄은 제안대로지만 마지막 줄의 마침표가Y80으로 내려간다. 종료 포인터/글자 수는 정상이다. 3줄 기대값 assertion 실패로 최종 산출물을 만들지 않았다.

## 앞선 설명 정정

`v371_wordwrap_trial/trial.json` csv:4의180px after.rows도 실제로는4줄이며 마지막 줄은 마침표 하나다. 따라서 미리보기와 실제 슬롯 경로가 다르다는 초기 설명은 틀렸고, 둘은 이 관측에서 일치한다. 사용자가 붙여넣은3줄을 그대로 받아들여 “총3줄 유지”라고 설명한 것이 잘못이다.

기존 자동 검사는 alphanumeric 사이의 어절 끊김만 잡고 문장부호의 행두 고립을 잡지 않았으며4행까지 허용해 layout_candidate로 분류했다. 이는 의미상 좋은 조판/사용자 승인3줄을 보장하지 않는다. 후속 도구에는 문장부호 고립을 별도 예외로 검출해야 한다. 현재 광역 도구를 이 요청에 섞어 수정하지 않았다.

## 대기 중인 선택

창/글꼴/띄어쓰기를 유지한다면 마지막 어절까지 함께 내려4줄로 시험하는 것이 후보이다. 예: 마지막 두 줄을 `그게 우리 일족의` / `규율이야.`로 나눈다. 사용자 확인 후 이 국소 배치로 CPU/디스크 검증을 진행한다. 실제 초반 장면의 창/초상화/게임 화면 확인은 남아 있다.

초안 스크립트는 실패하는 검증을 보존한 미완료 실험이며 실행 가능한 배포 빌드로 취급하지 않는다. bible/changelog는 새 게임 변경이 없어 유지, test_log/codex_notes 기록.
