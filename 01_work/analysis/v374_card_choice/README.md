# V374 카드 라벨 + 제보 선택지 위치 수정

2026-09-10 사용자 승인: 두 건을 함께 수정. V373 기반이며 V372 조판 방식은 포함하지 않는다. 원본/기존 빌드/메모리카드/사용자 상태저장/CSV는 변경하지 않았다.

## 변경 범위

- PSX.EXE 0x78078/0x78080: 각각 원문 카드 1/2 라벨 8바이트 슬롯을 `카드 1`/`카드 2` + 종료/패딩으로 교체. payload 5바이트, 슬롯 8바이트 이내. 포인터/카드 감지/초기화/입출력 코드 및 글꼴은 불변이다.
- C1/SC021.DAT #2425: E286 슬롯 completion 0x452FF의 12→14, 실제 1바이트. 제보된 초상화 대화창 너비는 180px이다. 질문 마지막 글자까지 출력한 뒤 자동으로 다음 줄로 진행하고 E601이 다시 개행하여 빈 줄이 생겼다. 그 E601만 E2 복귀 시 건너뛴다. 디스크의 본문·E601·E503·NUL·후속 이벤트·선택 인자는 그대로다.
- E286의 스크립트 영역 호출은 해당 파일에서 0x46F0E 한 곳임을 확인한다. 같은 본문의 SC031은 이번 제보의 로드 파일이 아니므로 변경하지 않았다. 넓이가 다른 미검증 호출에 일반화하지 않는다.
- 총 2파일, 3쓰기 범위 17바이트, 실제 차이 11바이트. 나머지 162개 멤버 동일. 전역 커서 간격/위치 코드, 타이틀 및 글꼴 불변.

## 검증

- 기존 계보 prepare에서 V373을 byte-exact 재생성하고 V374 반복 출력 동일성 검사.
- 상태 SHA256 `0C1BC09F1E858EFD0E4C9540329B93D99F9452F37EBC08E71D346D3DF6F79BE2`, V373 제목 및 EXE 앵커 확인. SC021 0x43000..0x48000 전체가 RAM에 유일하게 일치한다.
- 실제 MIPS 출력기 CPU: 수정 전 26글자 전체 XY 및 끝 포인터가 캡처와 일치. 수정 후 질문 14글자 XY 불변, 선택지 12패킷 모두 정확히 Y-16, 행 Y32/48/64. 끝 80115F2D 불변.
- 기존 커서 계산 루틴의 선택 0/1 결과는 (108,50)/(108,66). 선택 본문 시작 (122,48)/(122,64)와 기존의 x-14/y+2 관계를 유지한다. baseRow=1과 선택 인자/분기는 바꾸지 않았다.
- 카드 라벨 실제 출력기 CPU: 각각 4패킷, Y48/64, 숫자 글리프가 서로 다른 73/10으로 출력된다. 원본 카드 선택 호출자의 소스/좌표는 `audit_arc1_v371_card_labels.py`에서 별도 확인했다. 카드 화면 최종 GPU와 정상 카드 감지→선택→불러오기/저장은 아직 미검증이다.
- 이전 V373 검사 함수를 새 상태에 그대로 쓰려던 초기 시도는 228px 가정에 걸려 중단됐다. 새 상태의 실제 180px 조건으로 전용 검증기를 만들었다. 커서 검증의 Unicorn 종료주소 지정은 기대 PC와 달라 실패하여 기존 검증 방식의 명시적 code hook 종료로 바꾸고 두 선택 위치를 검증했다. 게임 코드를 바꿔 우회하지 않았다.
- 원본 트리에서 디스크 생성, 506 data LBA 유지, 패치 멤버 164개 readback 일치, 전체 507 extent/size 동일. 변경 29섹터 EDC/ECC 58검사 PASS. V373 대비 선언되지 않은 payload 차이 0.
