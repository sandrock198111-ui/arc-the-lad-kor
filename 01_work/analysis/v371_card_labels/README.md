# V371 카드 선택 라벨 조사 — 2026-09-10

게임·메모리카드·상태저장 파일은 수정하지 않았다.

## 확인된 원인 경계

- 원본 PSX.EXE `0x78078` = `BC 31 95 12 00`, `0x78080` = `BC 31 95 13 00`: 카드 1/2 라벨. V371에서도 두 문자열 및 포인터 테이블 `0x78088`이 원본 그대로다.
- 원본과 V371의 `0x8012D660`을 각각 격리 CPU 실행했다. 출력 함수 `0x8016B248` 진입에서 인자를 수집하고 그 함수만 반환시켰다. 양쪽 모두 `(56,48,0x80192878)` 및 `(56,64,0x80192880)`을 호출하고 선택 최대 인덱스 1을 설정한다.
- 현재 한글 코드 매핑으로 두 문자열 모두 ` 정호 `로 해석된다. 원래 숫자 1/2에 해당하는 서로 다른 코드도 현재는 공백으로 대응한다. 사용자 축소 이미지의 정확한 자형은 GPU 재현으로 확정하지 않았다.
- 하단 질문은 `build_ui_safe_v31.py` SYSTEM_TEXTS의 포인터 `0x781C4`에 포함되지만 상단 카드 라벨 포인터 `0x78088/0x7808C`는 포함되지 않는다. 번역에서 남은 원문 코드가 변경된 한글 글꼴로 소비되는 경로를 확인했다.
- 이는 카드 손상/내용 중복의 증거가 아니다. 카드 감지부터 선택까지의 정상 플레이, 최종 GPU 및 저장/불러오기는 이번 실험 범위 밖이다.
- 재현: `python -X utf8 02_scripts/audit_arc1_v371_card_labels.py`. 처음 unicorn import 실패 후 저장소의 기존 `01_work/tools/cursor_verify` 경로 사용으로 해결했다.

## 추가 선택지 제보

- 새 상태 SHA256 `0c1bc09f1e858efd0e4c9540329b93d99f9452f37ebc08e71d346d3df6f79be2`, 제목 V373_TWO_REPORTS_TEST.
- 본문만 보면 SC021/SC031 중복이지만 `0x43000..0x48000`의 전체 대조는 `C1/SC021.DAT`만 RAM 1122304에서 일치한다.
- CSV #2425, `0x46F0E`: `싸우게 되는데, 괜찮을까? / 괜찮아 / 그만둘래`. 캡처 문자 Y는 32/64/80으로 둘째 줄이 비어 있다.
- 현재 슬롯 E286 completion=12. 뒤 선택 이벤트의 baseRow는 이미 1이다. 따라서 전역 커서 간격을 바꾸거나 baseRow를 무조건 1 감소시키면 안 된다. 텍스트의 빈 줄 원인을 CPU 재현하여 선택 Y48/64와 기존 커서를 함께 확인한 뒤 국소 수정할 계획이다. 아직 미수정.
