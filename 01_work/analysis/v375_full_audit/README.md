# V375 아이템·스킬·UI 전수 목록 조사

조사일: 2026-09-10. **게임 수정 없는 원인 조사**다. 최종 행별 집계는 `summary.json`, 전체 UI 판정은 `ui_review_all.csv`, 오류·미확정 목록은 `findings_and_unknowns.csv`에 있다. 같은 오류가 여러 화면에 반복되므로 영향받은 행 수를 독립적인 버그 수로 해석하지 않는다.

최종 집계: EXE UI723행 중 의미 일치456, 허용 축약129, 결함102, 빈 슬롯20, 전용 HUD10, 미확정6. DAT868본문 중 의미 일치487, 허용 축약188, 결함99, 미확정94. **전행을 검토했으며, 미확정을 통과로 세지 않았다.**

## 결론과 우선순위

단순한 설명 두 줄 교환 문제가 아니다. 초기 번역의 캐릭터 ID 대응 오류와, 텍스트가 아닌 명령·구조 데이터를 글자로 재인코딩한 손상이 함께 남아 있다.

1. **이벤트 명령 손상: 9개 DAT, 24곳.** 그중 6곳은 앞선 명령의 인수도 바뀌었다. 물의 신전 `8/S8041.DAT:0x47924`는 원본 `14`가 현행 `27`로 바뀌었다. 앞선 두 `0B` 명령부터 실행하면 원본은 `0B,0B,14,21` 후 정상 반환1, 현행은 `0B,0B,27,00,028C` 후 실패 반환0이다. RAM 복사본에서 문제 바이트를 원본으로 돌리면 원본 결과와 일치한다. **이것은 실제 명령 처리의 차이를 증명하지만, 제보자의 진입 화면을 직접 재현한 것은 아니다.** 상세: `event_integrity.json`.
2. **오돈 명령 포인터 손상.** EXE `0x79210`의 포인터가 원래 핸들러 레코드에서 BSS 주소로 바뀐다. 원본 초기화·디스패처가 이 포인터를 따라가 함수를 호출한다. 실제 게임에서 해당 행동을 하는 상황의 RAM 값과 증상은 추가 재현 대상이다.
3. **히트 월 불꽃 객체 상태값 손상.** 배우 데이터 110레코드 중 88·89·90의 61바이트가 다르다. 실제 생성되는 불꽃88의 12바이트 중 상태 필드가 `0000→008A`로 변했다. 원본 코드의 복사·상태 갱신·첫 분기를 실행하면 원본은 정상 경로, 현행은 상태 명령30 경로로 간다. 89·90은 일반 생성 경로가 확인되지 않아 같은 수준의 실사용 결함으로 세지 않는다. 상세: `skill_integrity_followup.json` 및 후속 MD.
4. **스프라이트 속성·음성 ID·색상 데이터 손상.** `0x7C1C0`, `0x7E0D0`, `0x7E7FC`. 음성 ID480은 음수로 바뀌어 범위 검사에서 거부되고, 색상 키프레임은 `(224,48,48)→(225,210,48)`로 바뀐다. 화면·음성의 현장 재현과 코드상 소비 증거를 구분한다. 상세: `nontext_pool_followup.md`.
5. **캐릭터·효과 설명 오류.** 고겐/이가 및 다크 대응명 교환, 부활 효과의 시전자/수혜자 역전, 심안법의 단일 적 제한 오기, 거의 확실한 아이템 드롭을 희귀 아이템 획득으로 바꾼 설명, 회복량 편차 효과 누락 등이 있다. 지명·스킬명·아이템명 오독과 화면 간 명칭 불일치도 전체 행별 목록에 포함했다.

## 최초 아이템 제보의 정확한 원인

- 원본 캐릭터 이름 ID4는 ゴーゲン, ID5는 イーガ이다. 현행은 각각 이가, 고겐으로 반대다. 초기 `02_scripts/ui_full_v26_data.py`부터 이 순서가 존재한다. 다크 캐릭터 이름104·105도 반대다.
- 강력한 지팡이와 지옥의 스코프의 장비 속성·장착자 판정은 원본과 동일하다. 장비41의 소유자 값5는 원본 캐릭터4 고겐, 장비42의 값6은 원본 캐릭터5 이가에 대응한다.
- 따라서 설명 두 줄을 맞바꾸면 잘못 고치게 된다. 캐릭터 이름의 ID 대응을 먼저 바로잡아야 한다. `스누프`는 원문 スコープ의 별도 음역 오류다.

## 왜 기존 검사가 놓쳤는가

- 초기 UI 목록의 원문 판독·이름 순서가 잘못됐고 이후 빌드가 이를 이어받았다. 포인터와 표시 폭이 맞는 것만으로 ID·의미 대응까지 검증되지 않는다.
- `check_build.py`의 `KNOWN_BURIED`에는 `0x82634`, `0x8299C`가 검사 예외로 남아 있다. 예외는 해결을 뜻하지 않는다. 이번 원본 글리프 대조에서 전자는 負, 후자는 炎으로 확인했다.
- 원본 추출 CSV에는 대사가 아닌 이벤트 명령도 들어 있었다. 재인코딩이 이 범위를 신뢰해 숫자를 글자로 바꿨다. 물의 신전 바이트는 보관 빌드 V239에서 정상, V240부터 손상된 것을 확인했다.
- EXE의 NUL로 나뉜 영역이나 글자처럼 보이는 포인터 대상을 문자열로 간주한 처리도 문제다. 색상 손상은 V177→V178, 나머지 세 구조 손상은 확인 가능한 V229→V231 사이에 들어왔다. 원인·빌드 해시는 구조 보고서에 기록했다.
- 이번 조사에서도 디코더가 모르는 코드, 읽기 어려운 원문, 실제 소비 경로 미확정 항목은 통과로 처리하지 않는다.

## 실행·구조 검증

- 설명창의 비어 있지 않은 154행: 실제 MIPS 출력기를 346시나리오로 실행, ABI634호출과 패킷 경계 통과. 다른 도움말 그룹·상주 코드 보존. GPU 표시, BIOS 숫자 포맷, MP 구슬까지 확인한 시험은 아니다.
- 장비64×6바이트 및 소모품32×4바이트, 총96속성 레코드는 원본과 동일하다.
- 주요 인물의 유효 스킬 슬롯·랭크119조합에서 선택값과 24바이트 행동 레코드가 원본과 동일하다. 실제 플레이에서 모든 랭크를 습득해 사용한 수는 아니다.
- 행동 데이터 구간6,168바이트 및 선택 포인터110개·선택 데이터608바이트의 보존을 확인했다. 배열 길이를 실제 사용 가능한 기술 개수로 해석하지 않는다.
- 심안법은 원본의 범위 셀 표기·대상 수집·대상 목록 전체에 플래그를 쓰는 코드를 추적했다. 원본 CPU의 목록 순회는 두 대상을 모두 고정하므로 `적 하나 고정`은 틀리다.
- 분석 도중 발견한 CSV 문자 인코딩 손상은 분석 산출물에서 복구했다. 게임·정식 번역 파일은 변경하지 않았다.
- 炎 라벨 `0x8299C`의 E0AC를 실제 네이티브 출력기로 실행했다. 14/12/6폭 모두 빈 셀196을 가리키며 현행 COMM의 해당 픽셀은 전부0이다. 이 결과는 초기 `extra_system_review.csv`의 미확정을 대체하며 통합 CSV에 반영했다. `flame_glyph.json` 참조. 해당 메뉴의 GPU 재현은 별도다.
- EXE 전체 ASCII 포맷 후보79개는 전부 원본 바이트와 동일하다. 그중 UI 숫자 포맷27개에는 초기 목록에서 빠진12개가 있어 최종723행에 추가했다. 콘솔·SDK 후보49개와 명령바이트 오검출3개는 UI 의미 판정에 합산하지 않았다. 지정 출력 함수·숫자 래퍼의 직접 호출95곳도 목록화했다. `format_census.json`, `direct_print_calls.csv` 참조.
