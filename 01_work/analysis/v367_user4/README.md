## 1·2: 커서 높이

- 실제 1번은 둘째 선택 ‘고겐’, 2번은 첫째 ‘토슈’에 커서가 있다.
- 활성 삼각형: 1번 (36,50)/(43,56)/(36,62); 2번 (36,34)/(43,40)/(36,46).
- 텍스트 행 Y32/48/64/80. 커서 이동 간격16px는 맞고 누적 이동 오차가 아니다.
- 캡처 VRAM에서 복원한 실제 폰트 획: 토 Y33..42, 슈 Y33..46, 고 Y49..58, 겐 Y49..62.
- 바로 옆 첫 글자 ‘토/고’ 획 중심37.5/53.5에 비해 커서 끝40/56은 각각2.5px 아래다.
- 단어 전체 높이 중심39.5/55.5와 비교하면0.5px 아래다. 따라서 “모든 글자의 중앙에서2.5px 아래”라고 일반화하면 안 된다.
- 제안은 선택전용 Y 보정+2→0(2px 위로), 간격16과 X는 그대로 유지. 아직 적용/검증한 수정이 아니다.
- 해당 조정은 다른 선택창에도 적용되므로31창 및 받침 있는 첫 글자에서 시각 재검토 필요. 전투 공유삼각형/전투커서는 수정하지 않는 범위로 계획한다.

## 3: 빈줄

S6054:43E3C. 실제 출력:

    문제: 파렌시아 성의 왕을 모시는
    [빈줄]
    대신의 이름은?

기존 강제개행은 ‘모시는’ 직후다. 자동 행 전진과 강제개행이 이어져 Y32→64로 넘어간다.
V367 전체 CPU 결과에서도 이 항목만 사용행 사이32px 간격이 확인된다.
앞선 검증은 occupied Y 종류 수만 세어 빈줄을 놓쳤다. 행 사이 빈칸과 강제/자동개행 중첩 검사가 필요하다.

## 4: 한 글자 고립

S6054:4429E. 실제 출력:

    문제: 다른 공간에서 적을 공격하
    는
    아크의 기술은?

‘공격하는’ 마지막 ‘는’이 자동개행되고 바로 다음 강제개행으로 셋째 줄이 생긴다.
원문 누락/폰트 오류가 아니라 현재 한국어 조판 문제다.
단순4행 이하 검사는 통과하지만 올바른 레이아웃은 아니다.
