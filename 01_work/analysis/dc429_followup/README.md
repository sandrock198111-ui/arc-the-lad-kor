## 확인 사실

- 상태 1 SHA256 `53c837a5265b2519ba3ce8f44bce4ebf7b01a74fc96db7d25f25ea12b285724c`는 이전 업로드와 파일 전체가 같다. 내부 식별자는 V361_SKILL_COMPACT_TEST다. 사용자가 한글 화면 확인 후 새로 저장했다는 상태를 아직 확보하지 못했으므로 저장 후 일본어 회귀 원인을 확정하지 않는다.
- 상태 2의 고정 대사 객체 0x801F9D88은 limit/count 64/64. #1666, 6/S6041.DAT:0x487C0의 실제 확장 스트림은 66글리프 토큰이며 마지막 `지.`가 표시되지 않았다. 공백을 포함한 출력 개수와 파일 바이트 여유는 별개다.
- 상태 3의 #1697, 6/S6053.DAT:0x47CBC는 자동 줄바꿈으로 `운`이 별도 행이 된 뒤 E6 01이 다시 줄을 바꾼다. 표시 행을 늘리는 강제 개행과 자동 개행의 중복을 검사해야 한다.
- 정식 번역표 2,878행의 스승/사범 검색 결과는 #1697~1699 세 행이다. #1697 한 문장 안에서 사범님/스승님이 섞이고, #1698~1699에도 스승님이 남았다. 모두 같은 파일이다.
- 상태 6의 현재 source pointer 0x80112987 주변은 6/S6054.DAT의 0x439xx와 일치한다. 본문 시작 0x4395A부터 종료까지 원본과 V362 바이트가 같다. 정식 원문/번역 CSV 양쪽에 이 낮은 주소의 문장이 없고 추출기 SCRIPT_START=0x45000이다. 런타임으로 도달한 추출 누락 한 건을 확인했다.
- 원본 COMM 글리프 직접 렌더 결과: `ラマダ僧：修行をつみにまいられたのですか？ / その通り。 / とんでもない。` 원본 근거 이미지는 로컬 `slot6_original_glyph_evidence.png`. 원문 코드를 현행 한글 아틀라스로 소비해 깨지는 것이므로 단순 번역 표현 문제가 아니다.

## 선택 커서 보호 조건

사용자가 기존 위치/이동폭 수정 보존을 명시했다. E5 들여쓰기, E6 줄바꿈, 삼각 커서와 텍스트 전진폭은 같은 값이 아니다. 과거 V191은 질문 개행을 지웠더니 글자만 올라가고 커서는 남는 실기 실패가 있었다. V347 기록의 16px 행 간격은 두 번째 선택 상태의 실제 이동 검증 완료를 뜻하지 않는다.

수정 전에 현행 EXE의 기존 커서 경로와 화면별 선택 배치를 고정하고, 두 항목 각각의 커서 위치·이동 거리·끝에서의 동작을 확인해야 한다. 전역 간격을 임의 변경하지 않는다. 현재 한 상태만으로 이동 범위 런타임 통과를 선언하지 않는다.
